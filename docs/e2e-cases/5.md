# End-to-end cases — #5 Drizzle client, write-store migrations and integration test harness

Derived from issue #5 (Covers: R1, R2, R3 constraints, D1 DDL). Cases come from
the story's acceptance criteria, not from the implementation.

Cheapest first; probes last.

### 5-2

- Actor: admin starting a flash sale on a product a colleague has already put on sale
- Covers: criterion 2 of #5
- Precondition: table `promotions`, its GiST exclusion constraint on product-level promotions, migration `0000` applied
- Given: two active product-level promotions overlapping in time for the same product
- When: the second is inserted
- Then: PostgreSQL raises SQLSTATE 23P01
- Measure: none

### 5-3

- Actor: admin creating a promotion before deciding what it applies to
- Covers: criterion 3 of #5
- Precondition: table `promotions`, its `status` enum including `draft`, its target CHECK constraint
- Given: a `draft` promotion
- When: it has a `product_id` or `category`
- Then: the CHECK constraint rejects it; and an `active` one without a target is rejected
- Measure: none

### 5-1

- Actor: none (probe)
- Covers: criterion 1 of #5
- Precondition: `npm run db:migrate`, migrations under `src/shared/db/migrations/`
- Given: an empty database
- When: `npm run db:migrate` runs
- Then: tables `products`, `promotions` (with both GiST exclusion constraints and the `draft` status), `pricing_rules`, `ingestion_jobs`, `ingestion_chunks` and all enums exist exactly as in the spec §3
- Measure: none

### 5-4

- Actor: none (probe)
- Covers: criterion 4 of #5
- Precondition: `tests/integration/` Vitest project and its `globalSetup`
- Given: the test harness
- When: two integration test files run
- Then: each gets its own database (created from a template) and migrations are applied once in `globalSetup`
- Measure: none

### 5-5

- Actor: none (probe)
- Covers: criterion 5 of #5
- Precondition: the `pricing_rules` migration, table `pricing_rules`
- Given: `pricing_rules` migration
- When: applied
- Then: the default ingestion rules are seeded (markup by category, bulk-stock discount) as json-rules-engine JSON
- Measure: none
